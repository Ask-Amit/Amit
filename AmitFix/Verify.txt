WHAT THIS IS
"Amit" is a free companion web app (Bible study, a daily home page, books/accounting tools, chat) that lives online at https://ask-amit.github.io/Amit/ and
stores a person's data in their own online account. Separately, a person MAY install "Amit's helper" on a Windows computer. The helper is
a small set of PowerShell scripts and two small C# programs that let the website do things a web page cannot: show Computer Health readings,
type spoken words into any program ("voice typing" / Whisper mode), and so on. It is installed per-user (no administrator rights).
The page https://ask-amit.github.io/Amit/AmitFix/AmitFix.html is where a person can fix, quiet, remove or reinstall the helper.

BEHAVIOURS THAT WILL LOOK SUSPICIOUS TO A SCANNER, AND WHY THEY ARE THERE (verify each)
 1. A system-wide LOW-LEVEL MOUSE HOOK (amit_whisper.cs; search SetWindowsHookEx: the id is 14 = WH_MOUSE_LL, mouse only). It watches for the
    chosen mouse button being HELD for a moment, so the person can speak and have words typed. CLAIM: there is no keyboard hook (no WH_KEYBOARD_LL,
    no GetAsyncKeyState/GetKeyboardState), no clipboard access and no screen capture of other programs. The only image it draws is its own small overlay.
 2. It TYPES text into other programs (SendInput with Unicode characters). That is how spoken words appear where the cursor is. CLAIM: it types only
    the recognised speech, and only into a text box that has keyboard focus; otherwise it shows a message and types nothing.
 3. The SPEECH ITSELF: audio is captured by a separate browser window (Edge or Chrome, own profile folder) using the browser's built-in Web Speech
    feature, so audio goes from the browser to the browser vendor's own speech service. CLAIM: Amit does not record, store or upload the audio or
    the words; the words travel only from that page to the helper on localhost and are then typed. (Check amit_whisper.html and the /api/whisper routes.)
 4. A LOCAL WEB SERVER on localhost:8710 (amit_bridge_server.ps1; search HttpListener, Prefixes.Add: it binds to localhost only). The Amit website, in the
    person's own browser, talks to it. The whisper routes require a secret token generated at each start. CLAIM: it does not listen on the network.
 5. RUNTIME COMPILATION and HIDDEN POWERSHELL: the helper compiles amit_whisper.cs with Add-Type when it starts and runs as a hidden PowerShell process.
    This is how it avoids shipping another binary; the source it compiles is the file listed below.
 6. START-WITH-WINDOWS: one value under HKCU\Software\Microsoft\Windows\CurrentVersion\Run named AmitComputerHealth, and two per-user protocol
    handlers (HKCU\Software\Classes\amit-tracker and amit-helper) so the Amit website can open the helper. Removal deletes all three.
 7. The installer can install NODE.JS and the CLAUDE CODE command-line tool (via winget / npm) when they are missing, to read receipts for the AmitBooks
    app. See Install_AmitTracker.ps1 step 1b. Removal leaves them because they are general-purpose.
 8. It READS two local files to answer yes/no questions: it checks whether Claude Code is signed in by looking for a token in the Claude Code credentials file
    under the person's profile folder, and reports only true/false to the website (search ".credentials.json" in amit_bridge_server.ps1; the token is never sent).
 9. VIRUSTOTAL: app_behavior_watcher.ps1 can look up a file's hash on VirusTotal, only if the person has supplied their own API key. It sends hashes, not files.
10. UNSIGNED: no code-signing certificate has been bought yet, so Windows shows "unknown publisher". Expect that and low-reputation flags on new files.
11. DEVELOPER-ONLY COMPONENTS are in the public source and are inert on an ordinary installation: amit_mobile_watcher.ps1 is packed inside install-Amit.exe but the installer
    does NOT copy it into the installed folder (see $filesToCopy in Install_AmitTracker.ps1), and the helper starts it only if that file exists next to it (Test-Path in amit_bridge_server.ps1).
    If it were present it needs a local key file Database\supabase_config.md that exists only on the developer's computer, and stops with an error without it. The Ask Amit answering
    watcher likewise starts only if %LOCALAPPDATA%\AmitComputerHealth\ask_watcher.json exists.
    exists). Also, the helper contains a route (/api/coder-token) that writes a credentials file at a path under the profile folder for a developer workflow; it needs
    the developer's Amit folder to exist. We know these should not be in the public package and plan to move them out; flagging them is part of being honest.
    To let anyone read the developer-only script without hunting for it, a byte-for-byte plain-text copy and a plain-English walkthrough are published beside this packet (AmitFix/amit_mobile_watcher_source.txt and AmitFix/amit_mobile_watcher_explained.txt); compare the fingerprints below.

CLAIMS TO TRY TO DISPROVE (tell us if the code shows otherwise)
 A. The helper has no code that sends the person's files, keystrokes, clipboard, screen contents, passwords or browsing history anywhere. The only outbound web
    addresses in the code are listed in OUTBOUND DESTINATIONS below; check that list is complete by searching the source for http, WebClient, Invoke-WebRequest,
    Invoke-RestMethod, Socket and TcpClient.
 B. Computer Health readings (programs open, CPU/memory, installed software, drivers, events) are kept on the computer and served only on localhost; the Amit website
    (browser-side code, separate from this packet) can fetch them from localhost and, for a signed-in person, save a summary to that person's own online account.
 C. Removal (Amit_Fix.ps1, action "remove") touches only: the folder %LOCALAPPDATA%\AmitComputerHealth, the temp folder AmitInstallerFiles, the Run value, the two
    protocol keys, and the shortcuts Amit.url / Amit Live.lnk / Amit Tracker.lnk on the desktop; and it stops only Amit's own processes (matched by script name or
    by its private browser-profile folder). It does not touch documents, Edge/Chrome profiles of the person, or any other program.
 D. There is no persistence beyond the Run value and the two protocol handlers, no scheduled tasks, no services, no drivers, no firewall changes, no hosts-file edits.
 E. Nothing is downloaded and executed from the internet at run time except what the person explicitly asks for: the installer script can fetch its own files from
    raw.githubusercontent.com/Ask-Amit/Amit only when run standalone without the embedded copies, and winget/npm only for the optional Node.js / Claude Code step.

PERSONAL INFORMATION: what is and is not in this packet
No passwords, API keys, account numbers or emails are in the files listed. The public key for the online database that appears in the Amit website is a
"publishable" key designed to be public. The author's Windows user name was removed from the program paths (they now use the profile folder of whoever runs them). First names
and dates of the developer remain in some code comments as development history. The GitHub name Ask-Amit is the project's public identity and is in every download address.
Older versions of some files in the public repository's history still contain the earlier hard-coded paths; they were never secrets, but we mention it for completeness.

=== HOW TO TEST SAFELY ===
 1. Use a throw-away Windows computer, a virtual machine, or Windows Sandbox (Windows 10/11 Pro: turn on "Windows Sandbox", open it, copy the installer in).
 2. Before running, record: Task Manager > Startup apps; the contents of %LOCALAPPDATA%; the HKCU Run key (regedit). Or run Sysinternals Autoruns and Process Monitor.
 3. Run install-Amit.exe. Expected: a black window 10-20 seconds, a message that the computer is connected, a small tray icon, a desktop shortcut "Amit".
 4. Watch network connections (Process Monitor, TCPView or Wireshark). Expected: the website itself, github raw/pages if the standalone installer path is used, winget/npm if Node.js
    is installed, and local traffic to localhost:8710. Anything else is worth reporting to us.
 5. Run Amit_Fix.cmd or Remove-Amit.exe from https://ask-amit.github.io/Amit/AmitFix/AmitFix.html and compare the machine to step 2: it should return to how it was (except Node.js / Claude Code if they were added).

Questions, or something we missed? Please tell us, publicly if you like. We would rather be corrected than trusted.
