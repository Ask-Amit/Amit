# Tables used by this project (copied from CLAUDE.md 2026-11-14)

**Tables this project uses.** Table prefix is `Hel_` (the first three letters of "Helper", per the DATABASE TABLE NAMING CONVENTION). Every migration that creates one carries its Data API grants and row-level security in the same file. Each person sees and edits only their own rows. Also reads `users` and the Supabase Auth login. Which tables exist now: see Sessions_Start.md.

**Added 2026-11-17 (migrations 043 and 044, run by Ryan; local in Database\, not in the repo; prefix is lowercase `hel_`):**
- `hel_home_network` (user_id, computer, host, public_ip, reported_at; RLS: a person reads only their own). Written by `hel_report_home(p_computer, p_host)` (the Hub calls it every 4 minutes while the local bridge answers). Read by `hel_am_i_home()` (true when the caller's public IP, IPv4 equal or IPv6 same /64, matches a report under 15 minutes old). Helpers: `hel_caller_ip()`, `hel_same_network(a,b)`, `hel_net_probe()`.
- `hel_hop_tickets` (ticket, user_id, computer, created_ip, created_at, used_at; RLS on, no policies, so only the functions reach it). `hel_make_hop_ticket(p_computer)` (signed-in only; needs a recent home report on the same network) and `hel_use_hop_ticket(p_ticket)` (callable with the public key; single use, 3 minutes, same network). The Helper's /hop route calls the second one and also requires the ticket owner to equal the signed-in owner.

**Phones on a computer (Helper 2.08, 2026-11-18; a file, not a table):** `%LOCALAPPDATA%\AmitComputerHealth\pad_devices.txt`, one phone per line: `key|name|added|owner|phone id|last used` (the key is 32 hex and is the phone's pass to the Pad; owner = the Amit account id; phone id = made once by Amit Mobile and kept on that phone, letters and digits, 2 to 16; last used is written at most every 5 minutes). An older Helper reads the first four fields and ignores the rest. The phone is found again by its id (the hop sends `/hop?t=<ticket>&i=<phone id>&n=<name>`); a phone with no id is found by name; an older record named "Phone <id>" is adopted by that id. The name is set ON THE PHONE (Amit Mobile asks once; "This phone: ... (change)" on the Mouse and Buttons tile) and the computer keeps the latest one it was sent. Phones page (the Hub's Amit Phone tab shows it in an iframe of http://localhost:8722/pair, served from `amit_pad_pair.html`, which kept its old file name so the updater and installer lists did not change): list, Remove, and the pad on/off switch; JSON routes `/pair/list`, `/pair/revoke`, `/pair/switch` (localhost only, POST needs the X-Amit-Pair header). `/pair/add`, the QR pairing and `PairPage`, `AddDev`, `LanIp` were removed in 2.08 (old copies: Backups\AmitHelper\2026-11-18_before_old_pairing_removed\). Remove forgets a phone on this computer only: while the phone is signed in to the same account it can connect again.

**Tables this project does NOT touch:** everything owned by other apps (`hub_entries` except pursuit rows stamped program='AmitHelper', AmitBooks, AmitHealth, the `Ass_` tables, the testimony and profile tables).

## What it is (moved from the 2026-11-06 hand-off notes)
A screen where a person sets what every button of every mouse does. It is reached from the Amit Helper bar: the Settings group gets a **Mouse** button next to Sound. It lives in the Helper only (the Hub just opens it through the shared bridge and reads the database for display), because a web page cannot tell which physical mouse a press came from, and cannot remap buttons across Windows.
**Stage: DESIGN ONLY.** A working preview exists; NOTHING is built in the Helper for it. (The Voice menu and the previewer it touches are built and pushed: helper 1.68, installer 4.85.) Ryan has not yet said the preview is approved. The preview file itself is local by rule (`Previews\`).

## Ryan's decisions (settled) (moved from the 2026-11-06 hand-off notes)
- **Learn by pressing.** Each mouse's buttons are learned by pressing them (the preview shows them lighting up). Several mice are supported; each gets a ONE-WORD name; one is the PRIMARY mouse. Picking up a mouse switches to that mouse's configuration automatically; a mouse not yet learned is learned first (a new mouse cannot be finished until it has a name).
- **Primary mouse (fixed, never changeable):**
  - Left button: normal click, double-click, hold, always (clicking your way back from any mistake must always work).
  - Right button: click normal; HOLD opens the Amit Live ring (the Aurora); DOUBLE-CLICK opens the Helper bar.
  - Middle button: a single click ALWAYS starts Voice (built in helper 1.62); turning the wheel while Voice is listening opens the Amit menu (built in 1.63 to 1.68); a HOLD IS NOT USED (Ryan: "it probably won't be", the center already carries a lot). No double-click on it (its first click would start Voice).
- **Every other button** (back, forward, wheel tilt, wheel, extra buttons on the primary mouse; ALL buttons on any secondary mouse, even left and right) can have three settings: Click (its main job), Double-click, and Hold with its own time in milliseconds. A click is delayed by the double-click wait (about 300 ms) only when a double-click is assigned.
- **Actions a button can have:** keep as it is, send keys, run a Helper bar button (chosen as MENU first, then BUTTON), act as another mouse button, switch mouse set, do nothing.
- **Sets:** numbered sets per mouse (1, 2, 3, gaps filled), each with a label ("Everyday", "Design mode"). Switched by: a Helper bar button, a voice command ("mouse gaming set two"), a button assigned "Switch mouse set", or the Mouse tab of the Amit menu (the real list of sets shows there once sets exist; today that tab says no sets are set up).
- **Per-button Lock** (the person can lock any other button; it then shows read-only with "Unlock this button").
- **Keyboards are a SEPARATE future app** (the menu's Keyboard tab is greyed, "soon"). Do not build keyboard work here.
- **Where it lives:** the configuration is kept in a LOCAL FILE (so it works offline) AND in the database under the person's login (Hel_ tables, newer-wins sync per mouse), with a per-computer device binding (like `file_bindings.json`). New local capability = a new route on the shared bridge `http://localhost:8710` (SINGLE LOCAL CONNECTION STANDARD in the root CLAUDE.md); no new server. The same screen is served from the Helper locally and the Hub opens it.

## How the Helper must identify the mouse (proved on Ryan's two real mice, 2026-11-05) (moved from the 2026-11-06 hand-off notes)
- Windows raw input (`WM_INPUT`, `RegisterRawInputDevices` with `RIDEV_INPUTSINK`) names the source device of each press and movement but cannot block it. The low-level mouse hook (`WH_MOUSE_LL`) can block or replay a click but does not know the device. So: match each hook click to a raw-input report.
- Matching rules (tested, 107 of 107): a per-button FIFO of raw reports; wait about 3 ms; look back about 20 ms; when two mice press the same button almost at once the click is ambiguous and PASSES THROUGH; never block an unmatched or injected click (`LLMHF_INJECTED`, 0x1/0x2; Amit Live replays the right button with `SendInput` marked `MARK`); raw input runs on its own thread; a low-level hook that takes more than about 300 ms is removed by Windows without telling you.
- The ONLY mouse input the Helper hook handles today is in `ComputerHealth\Watchers\amit_whisper.cs` (`HookCb`, `HandleButton`). Do not add a second hook elsewhere; extend this one carefully (see the Voice-menu handoff for the lock-up episode and how it was made impossible).

## READ, the reading speaker on the Amit Live ring: how it is built (moved word for word from ComputerHealth\Sessions_Design.md by the 2026-11-15 clean-up; Read is part of the Helper)

**READ (the fourth choice on the Aurora, helper v1.42 / bridge v1.12, 2026-10-31):** a see-through speaker that stays on top of the screen and reads aloud, in the person's own saved Amit voice, whatever they point at, in any program. Choose Read on the ring, press the speaker (it shows a second gold ring = ready), then the VERY NEXT click or selection is read, once: a click reads from the clicked word to the end of its paragraph; a highlight reads exactly the highlight (Select All = the whole page). Then it goes back to waiting. A soft gold highlight (a click-through window over the desktop) shows the words being read. Press the speaker while it reads = pause, and the next click/selection is read instead (press again = resume). **Double click the speaker = the voice window** (voice, speed, pause between sentences, pitch, volume, Test, Save), interactive: changes are heard at once, carrying on from the word being spoken. **Dictation/Voice take priority:** Read pauses by itself when they start and resumes when they end (the highlight hides meanwhile). If Amit cannot read what was pointed at, it says so aloud and on screen. Esc or a right click on the speaker removes it. **How it speaks:** the natural voices (Brian) exist only in the full Edge, so the helper starts a hidden Edge window (page `amit_talk.html`, served at `/talk`, own profile `talk_profile`) only while reading and closes it 30 s later (~270 MB private / 15 processes while open: the heavy part; `--single-process` breaks it, do not use). **The voice comes from the login:** the Amit pages copy `contacts.voice_*` to the helper (`/api/talk/voice`, Amit site only; `amitSyncVoiceToHelper` in `amit_owner_contact.js`); a voice saved from the voice window is kept locally and handed back to the next Amit page that loads under the login, which writes it into the saved voice (`/api/talk/voice-save`, `/api/talk/voice-ack`). Full detail and the lessons learned: the old log (now in the Daily Sessions folder) (2026-10-31 Talk/Read entries). Not yet tested: Windows 10, browsers other than Edge, programs that do not share their text (clipboard path).


## Show Amit editor, how it is built (Helper 2.00, 2026-11-16)
The editor is the class `ShowAmitForm` in `ComputerHealth\Watchers\amit_whisper.cs`; one window per shot, as before. The drawing engine (`ZoomCanvas`), the layer model (`ShotLayer`, `LayerItem`), saving and opening (`.amitshot`), `DoSendToAmit` and the phone-photo note (`AttachPhoneNote`) were NOT changed; only the face was.
- **Layout (built by `BuildShellPanels`, `BuildShell`, `BuildLayerPanel`):** header (`top`: brand, the shot name box `title`, `ShotTabs` of the OTHER open windows, Retake = the old Clear and Recapture button, File menu), the "ADD TO YOUR PICTURE" row (`addbar`: eight small tools registered in `toolBtns`, five color dots plus the More button `bColor`, Fine/Medium/Bold = `widthMul`, undo, zoom buttons, Add capture = the old Capture button), the right panel `lpanel` (docked right, always visible: "On this picture" = `LayerCards` + the inspector for the active layer, then "Send to an app"), the Ask Amit bar (`askpanel`: `askBox` and the old Show Amit button `bAmit`, now labelled Ask Amit), then the status line.
- **Old controls:** the square buttons (Text, Save, Save View, Save As, Open folder, Live Shots, Layers, Open) still exist and keep their handlers but are hidden; the File menu calls the same methods (`DoSave`, `DoSaveView`, `DoSaveAs`, `DoOpenShot`, `ToggleSide` for Recent pictures, `DoOpenFolder`).
- **Every mark is its own layer:** `NewMarkLayer(type, tool)` runs when a drawing is finished (`OnToolUp`) or words are committed (`DrawText`) and names it "Arrow 1", "Words 2" and so on. `UndoLast` and `DeleteSelected` remove a layer that becomes empty (`delLayerGone` and `delLayerIdx` bring it back on undo). Old `.amitshot` files open unchanged; their multi-mark layers show as one item each.
- **Look:** `MakeButton` now returns `PillButton` (owner-drawn rounded button), so every older button is rounded too.
- **Ask Amit question:** `AskQuestion()` text is sent as "Question: ..." at the front of the words field of `SendShotToAmit` (non-phone path only). The phone-photo path uses its note box and hides `askBox`.
- **Send to an app:** four tiles (Receipts, Contracts, Job site photos, Quotes) are placeholders that only say "not built yet"; no app is wired. The real list is meant to come from the person's Amit account like the Helper bar buttons; not built.
- **Compile rule:** the bridge compiles this file with Add-Type, which treats warnings as errors (no unused fields or variables). Check with the Add-Type compile before installing (memory note `helper-compile-warnings-are-errors`).
- **Where to see it before it is built:** the design came from a preview (Amit Preview history, "Show Amit editor, current v1.48": the current editor, ChatGPT, Perplexity, Copilot, Grok and Amit versions, with Ryan's notes). The previous editor's whole source is backed up in `Backups\AmitHelper\ShowAmit_before_redesign_2026-11-16\amit_whisper.cs`.
- **Pulling in pictures (Helper 2.01):** `AddImageFromFile` (button "Add picture" and File > Add a picture from a file; the dialog starts in the Show Amit folder; click-to-place as before), `OpenAnyFile(path)` (static; File > Open a saved shot or picture; a `.amitshot`, or a picture with a `.amitshot` beside it, goes through `OpenLayeredShot`, any other picture opens in a new `ShowAmitForm`; `SetTitleFromFile` names it and, when the file is already in the Show Amit folder, makes it the saved file so closing makes no second copy), and `DropFiles` (File Explorer drag and drop onto the form or the canvas: each picture is placed as an image item through `PlacePendingImage`; a `.amitshot` opens in its own window). The zoom buttons live in a small panel floating at the bottom left of the canvas. When a picture is saved: ring captures at once (`StartQuick` calls `DoSave`), phone photos before they open, edits only on Save or when the window closes (`NeedsSave`, `OnFormClosing`); there is no autosave of edits.
- **Print and the icon (Helper 2.02):** `DoPrint` starts `AmitBar.exe --print` (the existing "Print from the screen" preview in `PrintCtl`, AmitBar.cs; "this window" is then the editor itself); the button `bPrint` (a `PillButton` with `PrinterGlyph()` and the word Print) sits next to Undo in the tools row; also File > Print and Ctrl+P. The header brand uses the real Amit icon through `LoadIconBitmap(iconPath)`: `amit_icon.ico` holds a single 256 x 256 PNG-compressed image, which `Icon.ToBitmap()` cannot read in .NET Framework, so the PNG inside the .ico is read directly; the drawn "A" stays only as a fallback if the file is missing.

## AURORA SETS, THE AURORA EDITOR AND BUTTON ICONS (added 2026-11-22, Helper 2.20 to 2.22)
- **ring_sets.txt** (%LOCALAPPDATA%\AmitComputerHealth, TAB-separated, read each time the ring opens): `active<TAB>Set`, `set<TAB>Set`, then per item `builtin<TAB>dictate|showamit|voice|talk|mobile`, `bar<TAB>Profile<TAB>Button<TAB>icon`, `menu<TAB>menu id<TAB>Label<TAB>icon`, or `profile<TAB>Name` (the whole bar profile, up to 10 buttons, followed automatically via bar_buttons.txt). At most 10 wedges; a missing file, empty set or unknown profile gives the five built-ins. Default is always present and editable (Reset to default).
- **Aurora editor**: menu id `aurora-editor` (Helper window on the ring's window thread, class AuroraEditorForm in amit_whisper.cs); every change is saved at once.
- **Icons**: a button's own icon comes from the bar: the bar writes bar_icons.txt (profile TAB button TAB icon) next to bar_buttons.txt (kept at two columns for the voice list). A ring wedge shows its button's icon unless the set gives its own letter or drawing; 7 or more wedges show icons only, with the hovered name in the middle. An icon may be an emoji or `img:<8 hex>` = a small PNG at icons\<8 hex>.png in the same folder (8 hex = first 8 of the PNG's SHA-1), saved by the bridge route /api/icons/save from the Hub (64 px) and read back by /api/icons/get. The database holds only the 12-character marker (hel_buttons.icon and the bridge's 12-character cut); the picture itself is per computer.
- **Bar buttons for the five original ring choices**: menu ids ring-dictate, ring-showamit, ring-voice, ring-talk, ring-mobile (each listed in MenuList with an AMIT-MENU marker); Dictate and Voice start at the pointer.
