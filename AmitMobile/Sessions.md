**2026-09-05 — Voice-input fix: SpeechRecognition doesn't work on Safari/iOS, replaced with plain text input.** Ryan tested the real app on his actual iPhone — the tap-to-talk mic button on the Daily Walk and Amit tiles (built on `SpeechRecognition`/`webkitSpeechRecognition`, the Web Speech API's speech-to-text half) did nothing at all. Root cause confirmed: Apple has never implemented that API in Safari on iOS, on any iOS browser (all of them are Safari underneath), so no browser choice on iPhone would have worked around it. Fixed in `AmitMobile.html` v1.01 → v1.02: both `amVoicePageHtml()` instances now show a plain `<textarea>` + "Send" button as the primary, always-present way to send a message — Enter submits (Shift+Enter for a newline). The phone's OS keyboard has its own built-in microphone/dictation button (a native OS feature, not a browser JS API), so "speak instead of type" still works correctly on iPhone with zero extra code. Where the browser DOES support `SpeechRecognition` (Chrome/Android), an optional small mic button still appears next to the text box — it now dictates INTO the box for the person to review/edit rather than auto-submitting on `onend` the way it used to. `callAmitBackend()` itself was not touched — the new `amSubmitTextInput()` function calls `amHandleVoiceInput(mode,text)` exactly as the old speech-recognition `onend` handler did. Text-to-speech (`amSpeak()`, Amit's replies read aloud via `speechSynthesis`) is untouched and confirmed still works in Safari. Confirmed correct for iPhone. `CLAUDE.md`'s Build Notes section updated with the correction inline.
