Before you read this report

    
This computer has only completed ? tracking session(s) so far — Amit needs at least 10 before it can fully tell real readings apart from a couple of things that only look like readings.

    
Two things worth knowing before anything in this report worries you:

    

      Some "sensors" are actually just labels, not measurements.
      
Certain hardware — NVMe drives especially — reports its own built-in safety limit (like "Critical Temperature: 84°C") sitting right alongside its real live temperature in the same data. That number isn't what the drive is running at; it's the maker's own line in the sand for "this would be too hot," reported the exact same way every single time, because it's a fixed spec, not something the drive is measuring right now.

    

    

      Some sensors exist on the board but aren't actually connected to anything.
      
A motherboard built to support, say, 10 fan headers doesn't always ship in a case with 10 fans installed — this one might only have 4. The other 6 headers are still real sensors the board reports on, they just don't have a fan plugged into them, so they'll sit at 0 forever. That's an empty header, not a failed fan.

    

    
Amit's way of telling these apart: watch each individual sensor across at least 10 separate tracking runs. A real reading moves around with real use. A spec label or an empty header never moves, ever — same exact number, every single time. Once a sensor proves itself constant across 10 full runs, it quietly stops appearing in reports and stops being flagged, automatically, no one has to fix anything by hand. And if it ever DOES start moving again in the future — say a fan actually gets installed in one of those empty headers — it comes right back the next time it's checked.

    
This computer just doesn't have enough history yet to make that call for every sensor. So a reading in the report below marked "Investigate" may turn out, a few sessions from now, to have been one of these — a label, not an emergency. It's not a false alarm exactly; it's an honest "not confirmed yet," and Amit would rather tell you that plainly than either hide it or cry wolf.

      ⚠️ Did Windows show a "blocked" message — even when double-clicking the desktop icon?
      
That's not a bug in Amit, and the desktop-icon trick above won't fix it — this is a separate, newer Windows security feature called Smart App Control, which blocks any program it doesn't yet recognize, no matter how it's opened. This is genuinely new: it wasn't blocking this before, and can start blocking a program it previously allowed, with no warning, usually after a Windows update. The permanent fix (a paid security certificate for this program) isn't in place yet — until it is, here's how to let it through:

      
1. Open Windows Security → App & browser control → Smart App Control settings.

      
2. Switch it to Off.

      
3. Try the desktop icon (or the browser launch button) again — it should open clean now.

      
One thing worth knowing before you do this: once Smart App Control is turned off, Windows only lets it be turned back on by doing a clean reinstall of Windows — it's not a switch you can flip back later. That's Microsoft's own restriction, not something Amit or this installer controls.

A second, bigger warning box then appears ("Make sure you trust..."). The real action is not the big "Delete" button — click the small ▾ arrow next to Delete, and choose Keep anyway (Chrome) or the equivalent option there.
