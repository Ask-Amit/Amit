**2026-09-18 (second fix, same day) — Errors tab still showed zero after the classification fix below, because of a SEPARATE real bug in `amit_bridge_server.ps1`'s `Get-LastUpdateInstallDate()`.** Ryan caught it live after testing: 4 real application errors from the last 4 days still weren't counting. Root cause: "last update" was computed as the single most recent successful install of ANYTHING in Windows Update history - and Defender signature updates (plus MSRT) install successfully multiple times a day, so "last update" was effectively always "a few hours ago." That pushed every genuinely recent error into "beforeLastUpdate" and hid it from the count, even though it was current. Fixed by excluding routine signature/security-intelligence titles (`Security Intelligence|Antivirus|Antispyware|Malicious Software Removal Tool|Defender`) from the "last update" search, so it reflects an actual meaningful Windows/driver/app update instead of background churn. Dev source only (`amit_bridge_server.ps1`) - needs the same re-sync-and-restart step as the fix below before it's live, and this one is bridge-server-side so a bridge restart alone (no dashboard reload) won't be enough on its own either.
